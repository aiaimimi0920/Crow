# AI 归档的 GPT 使用开关

Crow 观察台的「设置 → 采集运行配置」提供「允许使用 GPT 模型（PC2 AI 归档）」开关，以及独立的推理强度选项。新安装及旧配置缺失该字段时，开关默认关闭。

先点击「读取线上配置」，再开启 GPT 开关、填写模型路由（例如 `gpt-6.1-sol`）并选择推理强度（例如 `low`），最后「保存并应用」并确认。只有 PC2 回报应用成功、容器通过健康检查后，界面才显示参数已经生效；这不等于模型推理成功。

API Key 留空会保留当前密钥；密钥不会回显，也不会保存到本机草稿。修改模型可能产生费用。开关不会解除采集暂停、执行认证或重启认证浏览器。

关闭开关时，需要同时将模型路由改成可用的非 GPT 模型。关闭后，存活的资格池对象和既有资格缓存也不再允许 GPT 请求。GPT、Codex 和 o 系列都受此权限约束；图片、音频、embedding 等非文本模型仍被资格池排除。

## 配置合同与范围

设置 API 的 `ai` 组增加两个可选字段：

```json
{
  "allow_gpt": true,
  "reasoning_effort": "low"
}
```

`allow_gpt` 必须是 JSON 布尔值。`reasoning_effort` 支持 `none`、`minimal`、`low`、`medium`、`high`、`xhigh`，实际支持范围仍由模型上游决定。默认的 `false` / `none` 会规范化为旧配置形状，保持旧草稿、回执与版本比较兼容。

PC2 将权限写入 `CROW_ANALYSIS_ALLOW_GPT`（兼容 `FAPAI_ANALYSIS_ALLOW_GPT`），推理强度写入 `OPENAI_REASONING_EFFORT`。两权限别名冲突或值非法时拒绝使用，不静默回退。该观察台开关控制 PC2 AI 归档，不是 NAS 或其他进程的全局权限开关；这些进程须单独设置运行环境。

模型资格仍需五题测试、至少四题正确、有效期、共享限速与冷却。开启 GPT 不降低这些门槛。新配置的首选路由可以继续资格发现，不会被旧的已完成目录扫描永久遮蔽；共享冷却和扫描调度仍有效。资格池允许在已合格模型之间调度，配置路由不是“只允许这一模型”的独占锁。

## 保留容器时的安全应用

只改变 AI 连接、模型、密钥、权限或推理强度时，控制器按已检查的 exact container ID 替换受影响的 analysis Worker。它保留镜像、安全设置、环境和持久挂载，不执行 service-wide Compose recreation，也不删除旧容器。

旧容器停机后保留且禁用自动重启；新容器通过健康检查才发布 `active.json`。失败时尝试按 exact ID 恢复旧 canonical 容器；不能确认的结果记录为 `interrupted`，不自动重放。

此路径不支持顺便改变 Worker 数量、采集间隔、挂载、镜像或浏览器。如果这类变更遇到同 Compose labels 的保留备份，原有拒绝保护继续生效。不要为应用设置而删除备份或绕过保护。
