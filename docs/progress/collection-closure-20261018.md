# 链接扫描收尾与地区状态（2026-10-18）

## 行为约定

允许跨地区浅页覆盖，但不应让已开始的扫描长期无法继续。
本轮不迁移数据库、不清空任务、不重置页码、不更改认证安全门禁。

`parallel_sorts` 与 `breadth_first` 同时启用时，候选顺序改为：

1. 超过 30 分钟未被队列触达的候选优先，保护组内按触达时间从旧到新。
2. 其余候选优先续完已开始的扫描 job，同组未完成子任务较少者优先。
3. 保留浅页及既有地区、分类和稳定 key 顺序作为后续排序。

`updated_at` 是领取、失败、成功等队列触达时间，不是最后成功时间。
30 分钟是进入等待保护的阈值，不是任务完成时限；大量历史积压进入保护时，
可能先跨地区轮转。领取仍须通过来源 ownership、锁、有效租约和冷却检查。

收尾统计只在同一个 job 内聚合，避免不同来源任务互相影响；一个地区可能有
多个分类 job，因此这是推动地区逐步收尾，不是整个地区的排他锁或严格串行。
失败或来源阻塞不会被标记成完成，也不会通过该策略绕过暂停。

越过 max_page 的子任务在领取过程中被归一为 exhausted 时会重新定位候选窗口，
避免动态收尾排名变化导致同组剩余任务掉到旧 keyset cursor 前面。

## 工作台

- 待采集：尚无已完成扫描证据且没有有效执行租约。
- 待继续：已有扫描进度，但当前没有有效执行租约。
- 采集中：该阶段有有效执行租约；不是仅有 pending 队列。
- 等待重试 / 存在失败或阻塞：保留重试和失败事实。
- 本轮完成：沿用原有完整完成门槛，不以跳过、失败或已发现商品数替代。
- 详情、分析等待链接扫描收尾时显示“等待链接”，不冒充实际执行。

省、市从子地区汇总；浏览选中的地区只改变筛选，不改变调度。
执行徽标带亮色圆点，等待徽标采用中性色。9/12 表示扫描子任务数，不是页数、
商品数或剩余时间比例。状态反映最近一次刷新快照，不是 worker 的实时心跳。
